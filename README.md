# folio — 나를 더 잘 말하는 준비

이력서의 문구에서 예상 질문을 만들고, 답변의 키워드에서 꼬리질문을 연결하는 한국어 면접 준비 웹앱입니다. 기업·직무별 지원 건을 독립적으로 관리합니다.

**사이트 바로가기:** [career-interview-assi-web.vercel.app](https://career-interview-assi-web.vercel.app/)

## 실행

Node.js 22.13 이상이 필요합니다. 이 환경에서는 Node.js 24.19와 npm 11.9로 검증했습니다.

```bash
npm ci
npm run dev
```

`npm run dev`와 `npm run build`는 로컬 OCR/PDF 지원 파일을 `public/ocr`에 준비합니다. 이 파일은 Git에 포함하지 않으며 설치된 패키지에서 다시 복사합니다. npm 캐시는 쓰기 가능한 `/tmp/career-interview-npm-cache`를 사용합니다.

## 사용 흐름

1. 기업과 직무를 입력해 지원 건을 만듭니다. 최초 실행에는 가상의 인물·경력을 사용한 샘플이 표시됩니다.
2. 이력서 PDF를 업로드합니다. 텍스트가 있는 페이지는 직접 추출하고, 스캔 페이지는 한국어·영어 OCR로 인식합니다. 최대 20MB, 20페이지를 지원합니다. 인식한 텍스트는 수정할 수 있으며, 직접 붙여 넣는 방법도 제공합니다.
3. 이력서의 단어나 문장을 드래그해 선택하고 `질문 추가`를 누릅니다. 예상 질문과 답변을 직접 작성합니다.
4. 답변 작성란에서 문구를 선택하면 그 표현을 근거로 꼬리질문을 만들 수 있습니다. 후속 답변에서도 계속 반복할 수 있습니다. 마인드맵 카드에 표시된 답변에서도 선택·연결이 가능합니다.
5. 질문과 답변을 모두 작성한 뒤 준비 완료로 표시합니다. 검색·상태 필터·질문 목록으로 내용을 찾아볼 수 있습니다.
6. 질문 삭제 시 연결된 하위 질문도 확인 후 함께 삭제됩니다. 마인드맵 노드를 드래그한 위치도 저장됩니다.
7. 탭 옆의 `전체화면` 버튼으로 작업 영역을 넓힐 수 있습니다. 전체화면에서 질문 카드를 누르면 큰 중앙 팝업으로 편집합니다. Esc는 열린 팝업을 먼저 닫고, 다시 누르면 전체화면을 종료합니다.
8. 질문 목록은 연결된 질문을 묶어 `4-1 → 4-2`처럼 표시합니다. 앞 번호는 첫 질문에서 시작한 묶음, 뒤 번호는 묶음 내 순서입니다. 갈라진 질문에는 부모 번호도 표시되며, 검색·상태 필터를 적용해도 번호가 유지됩니다. 편집 화면의 `연결된 질문` 버튼으로 부모·꼬리질문 사이를 이동할 수 있습니다.
9. 질문 목록에서 첫 질문 번호 옆의 손잡이를 드래그하면 연결된 질문 묶음 전체의 순서를 바꿀 수 있습니다. 묶음 안의 부모·꼬리질문 순서는 고정됩니다. 검색·상태 필터를 해제한 뒤 사용하며, 손잡이에 초점을 두고 Space → 위·아래 방향키 → Space로도 이동할 수 있습니다. Esc는 이동을 취소합니다. 변경한 순서는 자동 저장됩니다.
10. 답변에서 암기할 키워드를 선택한 뒤 `굵게`, `글자색`, `배경색` 도구로 강조할 수 있습니다. `서식 지우기`는 선택 구간의 강조를 제거합니다. 서식은 자동 저장과 백업에 포함되며 질문 목록·마인드맵에서도 표시됩니다. `Ctrl+B`는 굵게, `Ctrl+Z`는 실행 취소입니다.
11. 답변에서 자주 쓰는 서식의 글자를 선택하고 `서식 저장`을 눌러 이름을 지정하세요. 다른 문구를 선택한 뒤 저장한 서식 버튼을 한 번 누르면 굵게·글자색·배경색이 함께 적용됩니다. 지원서별로 최대 8개까지 저장하며, 같은 지원서의 모든 답변에서 사용할 수 있습니다. 저장한 서식은 클라우드 동기화와 백업에 포함됩니다. 같은 이름으로 저장하면 기존 서식을 갱신하며, 저장 서식을 삭제해도 이미 꾸민 답변은 유지됩니다.

## 클라우드에서 여러 기기 사용

Vercel 배포와 Supabase 로그인·DB·비공개 PDF 저장을 지원합니다. 초기 설정과 기존 자료 이전 절차는 [클라우드 연결 안내](docs/CLOUD_SETUP.md)를 따르세요. 두 공개 환경변수를 설정하면 로그인 기반 클라우드 모드가 되고, 모두 없으면 기존 로컬 모드를 유지합니다.

## 로컬 모드의 저장과 백업

이력서 원본, 인식한 텍스트, 질문 트리는 **현재 브라우저의 IndexedDB**에 저장합니다. PDF 추출과 OCR은 브라우저 안에서 실행하며 이력서 내용을 외부로 전송하지 않습니다. 폰트와 OCR 모델도 앱에서 제공합니다. LLM API·서버·계정 없이 동작합니다.

다른 기기와 자동 동기화하지 않습니다. 브라우저 데이터 삭제·비공개 모드·저장 용량 제한에 대비해 백업을 보관하세요. JSON 백업은 이력서 **텍스트와 질문 트리**를 포함하며 PDF 바이너리는 포함하지 않습니다. PDF 원본은 별도로 보관하세요. 백업을 불러오면 기존 지원 건을 덮어쓰지 않고 별도 지원 건으로 생성합니다.

OCR 정확도는 원본의 화질·배치·언어에 영향을 받습니다. 스캔 결과를 확인하고 `텍스트 수정`으로 보완하세요. 암호가 설정된 PDF는 해제 후 업로드해야 합니다.

## 검증

```bash
npm test             # IndexedDB 저장, 트리 관계/삭제, 백업 검증
npm run build        # TypeScript 검사 + 프로덕션 빌드
npm run test:e2e     # 로컬 모드의 실제 브라우저 UI와 PDF/OCR
npm run test:e2e:cloud # 모의 Supabase 기반 로그인·클라우드 흐름
npm run preview      # 빌드 결과 실행
```

E2E는 시스템 Chromium(`/usr/bin/chromium`)이 있으면 사용합니다. 다른 실행 파일은 `PLAYWRIGHT_CHROMIUM_EXECUTABLE`로 지정할 수 있습니다. 시스템 브라우저가 없으면 `npx playwright install chromium`으로 설치합니다. 별도로 실행 중인 앱을 검사하려면 `PLAYWRIGHT_BASE_URL`을 지정합니다.

## 구성

- React · TypeScript · Vite
- React Flow: 질문 마인드맵과 확대·이동
- PDF.js: 텍스트 추출·스캔 페이지 렌더링
- Tesseract.js: 한국어·영어 OCR
- IndexedDB: 로컬 모드의 지원 건·PDF, 클라우드 미저장 복구 사본
- Supabase: 계정 로그인·지원 건 DB·비공개 PDF 저장
- Vitest · Playwright: 데이터 모델과 실제 사용 흐름 검증

`src/App.tsx`는 지원 건과 작업 화면을, `src/components`는 마인드맵·질문 편집기를, `src/lib`는 OCR·저장·백업·트리 관계를 담당합니다.
